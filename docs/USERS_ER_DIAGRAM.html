All User Entities — Attributes & Access

User Entity role value Attributes Panel / URL Operations
CUSTOMER customer id PK, name, email UK, password, phone, address, city /dashboard, /orders places → ORDERS (R1)
SALES STAFF staff id PK, name, email UK, password, role /admin/* (orders, customers, catalog view) processes → ORDERS; records → PAYMENTS (R7)
INVENTORY MANAGER manager id PK, name, email UK, password, role /admin/catalog/* creates → CATALOG_DESIGNS; uploads → CATALOG_IMAGES
ADMINISTRATOR admin id PK, name, email UK, password, role /admin/* (full access) creates staff accounts; manages → ORDERS; assigns → TECHNICIAN; updates → METAL_PRICES; records → PRODUCTION_LOGS; creates → INVOICES; generates → REPORTS
TECHNICIAN technician id PK, name, email UK, password, role /technician/* (no customer PII) updates → ORDERS (R2); records → PRODUCTION_LOGS (R3)
Conceptual vs Physical: Figure 1–2 show five separate user entities (Chen-style, like your sample diagram). Figure 3 shows the physical implementation: one users table with a role column.
