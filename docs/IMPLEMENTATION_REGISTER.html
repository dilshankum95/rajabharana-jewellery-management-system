4. Form Request — Validation Before Controller

class RegisterRequest extends FormRequest
{
    public function authorize(): bool { return true; }

    protected function prepareForValidation(): void
    {
        $this->trimStrings(['name', 'email', 'phone', 'address', 'city']);
    }

    public function rules(): array
    {
        return [
            'name'     => ValidationRules::personName(),
            'email'    => ValidationRules::uniqueEmail(),  // queries users table
            'phone'    => ValidationRules::phone(required: true),
            'address'  => ValidationRules::address(required: true),
            'city'     => ValidationRules::city(required: true),
            'password' => ValidationRules::password(),
        ];
    }
}

When controller method is store(RegisterRequest $request), Laravel runs validation automatically. If any rule fails, the controller never executes — user is redirected back with error messages.

5. Controller — Business Logic

public function store(RegisterRequest $request): RedirectResponse
{
    $validated = $request->validated();

    $user = User::create([
        'name'     => $validated['name'],
        'email'    => $validated['email'],
        'phone'    => $validated['phone'],
        'address'  => $validated['address'],
        'city'     => $validated['city'],
        'password' => Hash::make($validated['password']),
        'role'     => 'customer',   // RBAC role assignment
    ]);

    event(new Registered($user));
    Auth::login($user);

    return redirect()->intended(route('dashboard'));
}

9. Report Paragraph

The customer registration module was implemented using Laravel MVC architecture. The View layer presents a form with CSRF protection. The Form Request class validates input before the controller executes — checking formats, password strength, and email uniqueness against the users table. The Controller creates a User record via Eloquent ORM, assigns the Customer role, hashes the password, and logs the user in. Data is persisted in MySQL with a unique email constraint. After login, access to the dashboard passes through auth, verified, and customer middleware. RBAC ensures public registration cannot create staff accounts.
